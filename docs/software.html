Software

The Raspberry Pi program is C with the H-bridge interface in ARM assembly. It runs the motor, measures speed with the IR sensor, and talks to the iPhone app over Bluetooth Low Energy. This page describes it as checked at Checkpoint 2.

Each module protects its shared state with a mutex. Only the Bluetooth thread touches GLib or the Binc library; other threads hand it messages through g_main_context_invoke. The Bluetooth thread blocks all signals, so Ctrl-C always reaches the main thread, which shuts down Bluetooth, then the IR thread, then the motor, leaving the H-bridge disabled.

The H-bridge interface in assembly

The project requires the H-bridge interface to be ARM assembly with all GPIO access through the class library libE4235. hbridge.s provides:

  • HB_Init: sets up the four step pins and the enable pin, writing each pin low before it becomes an output.
  • HB_Step: moves one row up or down the eight-row half-step table (see Hardware) and writes the four inputs.
  • HB_Enable: switches the 4N25 enable on or off.
  • HB_RunSteps: the step-timing loop.

Step timing

HB_RunSteps uses the ARM generic timer (54 MHz on the Pi 4). Each step is scheduled for an absolute deadline, so the time spent in HB_Step does not change the rate. Linux pauses a real-time thread that never sleeps, so the loop sleeps through the early part of each step period and watches the timer only for the last 200 µs. Measured on the team's Pi at Checkpoint 1: no step more than 100 µs late at up to 3000 steps per second.

IR speed measurement

  • Sample GPIO25 every 1 ms. A new level must hold for two samples before it counts, which ignores single-sample glitches.
  • Time-stamp each blade arrival with the Linux monotonic clock. Arrivals closer than 5 ms apart (over 6000 RPM) are ignored.
  • The two-blade propeller gives two pulses per revolution, so the time from a blade back to the same blade two pulses earlier is one full revolution: RPM = 60 ÷ that time. Timing whole revolutions cancels any unevenness between the blades.
  • The reported value is the median of the last three revolutions, which rejects one bad count without lagging a steady speed.
  • With no blade for 4 s (or two blade gaps, if longer) the reading drops to 0 and old blade times are discarded.

The 1 ms sampling makes each revolution time uncertain by at most about 0.15% at 90 RPM, well inside Test A's 5% tolerance. At low speed the limit is how often a value arrives, not accuracy: at 30 RPM one revolution takes 2 s.

Bluetooth protocol

The Pi is a BLE peripheral advertising as PARMCO3, with one GATT service holding a command characteristic (the phone writes) and a status characteristic (the Pi notifies). Messages are single lines of ASCII text of at most 128 bytes. Pairing is "Just Works": BlueZ asks for an encrypted link soon after a phone connects, and without a pairing agent the link dropped after 30 s, which was found with btmon during bring-up.

Checkpoint 3: the app in control

From Checkpoint 3 the phone is the only control input. The keyboard keys are kept for bench work only; make run-app ignores them.

PartWhat it does
Control thread (real time, every 5 ms)Owns the motor. Runs the phone's commands and a state machine: stopped, running, moving to an angle, holding. Hands one log row to the logger each step.
Encoder thread (real time, every 5 ms)Reads the AS5600 and publishes the latest angle. A reading older than 0.1 s counts as an encoder fault, so a stuck read can never freeze motor control.
Calibrate zero, set to zero, angle targetCalibrate stores the encoder angle as 0°. Moves are measured by the encoder, the shortest way round, at the desired RPM, with up to two fix-up moves if a move lands a step or more off. Because they use the encoder, set to zero still works after the motor has lost steps.
Feedback holdAfter a move the H-bridge is switched off. If the blade is pushed more than 1° away, the program applies the coil pattern that matches the encoder angle (with the new assembly routine HB_SetIndex), steps back, and switches off again. Matching the pattern avoids landing a whole 7.2° pattern cycle away.
MaintainUses the encoder RPM. If the rotor falls more than 3.6° out of step it restarts in step and ramps back up; otherwise a gentle speed trim of at most ±15%.
LoggingThe specification's 13 columns at 200 rows per second, through a lock-free buffer and a separate writer thread, so file writes never delay control.

Bugs found on the bench and fixed. The Pi never sent status to a phone whose Bluetooth link was already open when the program started (iOS keeps a paired link open), so the app stayed "not calibrated" while commands still worked. The Pi now asks Bluetooth which phones are connected at start-up. Separately, several status notifications sent back to back could overwrite each other on the iPhone, so the whole status now goes in one notification.

Mac tests run the real control code against a simulated motor and encoder, including nudges, lost steps and a disconnected phone. Details: CP3 software.md and protocol.md.
